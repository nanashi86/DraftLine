# Changelog

All notable changes to DraftLine are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **Shooting schedule (DraftLine Core, free).** Plan → Stripboard → **+ Shooting Day**. Scenes go into shooting days
  in an order of their own (the script is never changed): drag a strip's handle, use its **Move to Day…** menu, or
  `Alt+↑` / `Alt+↓`. **Script | Schedule** switches between script order (with a quiet D3 on scheduled scenes) and
  shooting order (day headers with dates, pages, Day-Out-of-Days cast codes, places, needs, notes, a page target).
  Quiet advisory notes, never errors. Every change is a step in the one undo history. Cast numbers are fixed from the
  first shooting day (new characters get the next number; Rename keeps it; **Renumber cast…** only on purpose).
  Without a shooting day the Stripboard is exactly as before. Plan's tabs are now **Breakdowns | Stripboard | Budget**.
  A day's details open with its date and the page target; each cast code explains itself on hover, tap or click;
  **Renumber Cast…** lives in Plan's ⋮ on the Stripboard (the whole project's numbers), asks first, and is undoable.
- **Table Read (DraftLine Core, free).** ⋮ → Table Read… reads the script aloud: a narrator for scene headings and
  action and a voice for each speaking character, busiest characters first (voices are shared at slightly different
  pitches when there are more characters than voices). Read the current **Scene**, **Act** (as the Scene Board places
  it) or **Script** (from the top or **From here**), with previous / play-pause / next and 1× / 1.25× / 1.5×; the line
  being read is tinted and kept in view, never printed. **Voices…** lets you change any voice, hear a sample,
  Auto-Assign, and choose whether action, headings and parentheticals are read. In Chrome, Google's voices are
  preferred; they're online, so Table Read asks once per device before sending any text to Google, and uses on-device
  voices offline or if you'd rather. Voice choices are saved on the device, never in the project. It replaces the
  Table Read preview. Uses the browser's Web Speech API: no AI, no account, no new dependency.
- **Act labels in the Scenes sidebar.** Quiet ACT 1 / ACT 2 (2A, 2B) / ACT 3 labels, read live from the Scene Board's
  cards and its 3 Acts / 4 Acts switch.
- **Previews of what's planned.** **Shoot** (Lucide `file-check-2`) now follows Page | Split | Board; **Schedule** (`calendar-check`) and **Budget** (`calculator`) follow Breakdowns | Stripboard in Plan; and Write's ⋮ menu has **Table Read…** and **Co-Write…** after Reports. Each opens a short note about the planned feature and a **Close** button, and nothing else: your view, script and project stay exactly as they were, and focus goes back to what you clicked. Nothing is built behind them yet, there's nothing to buy, and no badges or prices sit on the toolbar. Plan keeps its clapperboard.
- **Roadmap: the approved plan.** DraftLine Core stays free forever and gains Table Read (next), then Schedule & Budget; **DraftLine Pro** is planned as a one-time purchase with Shoot and production revisions (deferred); **DraftLine Co-Write** is planned as an optional subscription that works with Core or Pro (last). New design note: `docs/specs/data-integrity.md` (what has to be in place before new project data ships).

The editor in its laptop frame is a real screenshot of DraftLine with the sample script *The Last Ferry*, in the dark or light version to match your theme. The root address still opens the editor straight away; nobody is sent to the Welcome page.

A small subset of Cousine (SIL Open Font License, about 350 KB for four styles, cached for offline use like Courier Prime) fills in the rest at Courier Prime's exact character width. Pages, line breaks, (MORE) / (CONT'D) and the title page are unchanged: all 288 pages of the reference scripts render pixel for pixel as before. Chinese, Japanese, Korean, right-to-left scripts and emoji still print as "?"; the export now names those characters and points to Print Script…, which keeps them.

- **Phones: steadier typing, faster opening (mobile hardening, round 2C).**
  - **Fixed: predictive text in a speech split across a page.** With a keyboard that composes words (Gboard, Samsung, iOS suggestions), typing at a page break could repeat letters ("not qququiquiet") or misplace words. While a word is being composed, the speech's page views and the cursor are left exactly as the keyboard has them. The break is placed again once the word is committed, with the cursor right after it. Tapping the element bar mid-word keeps the word, once. `npm run test:browser` replays these keyboards in Chromium.
  - **Long scripts open much faster, everywhere.** Script lines that appear together are measured together, in one layout instead of one per line. A 120-page script showed in about 1 s instead of 8.5 s (desktop and phone). Pagination, exports and the page itself are unchanged.
  - **Lighter typing on phones.** A split speech's page break is worked out again only when its text, type or lines change. The element bar skips locating the cursor's row when the whole line already clears it.
  - **Turning the phone keeps the cursor** on the same character, including inside a split speech.
  - **Phone text fields are at least 16px** (the script title, Title Page, Story Bible, Characters, Find & Replace, margin notes…), so iPhone Safari no longer zooms in when you tap one. Only on phone-width touch screens.
  - **The element bar's buttons keep a finger's width** when a large system text size narrows them. The hidden page-width copy now reads its real line height, so a browser's text-size boost can't misplace page breaks. Accessibility text scaling isn't restricted.

- **Phones: a readable writing view (mobile polish, round 2B).** On a phone-width touch screen the script is no longer a shrunken US Letter page. It's drawn to the phone's width at a reading size (16px Courier Prime, so Safari doesn't zoom on tap), keeping the screenplay's shape: bold capitalised scene headings, Character furthest in, then Parenthetical, then Dialogue, and Transitions on the right.
  - **Pagination is unchanged.** Page breaks still come from page-width wrapping, measured on a hidden copy of the script at print size, never from the phone's own lines. Page count, page breaks, (MORE)/(CONT'D), print, PDF and exports are exactly as on a desktop, and a script edited on a phone opens identically on a desktop. The copy is laid out just after the script appears, so opening a long script doesn't wait for it.
  - **Page breaks:** a faint divider with the page number marks where each real page begins. A speech split across a page shows "(MORE)" and "NAME (CONT'D)", and each side holds exactly that page's words. Typing, deleting, the arrow keys, formatting and undo all work across the break.
  - **Dual dialogue** is stacked and joined by a thin rule, with a quiet "spoken together" note.
  - **Scene numbers and CUE tags** sit small in the left margin. Margin-note marks sit in the right margin, with a larger tap area. Tapping one opens the Margin Notes panel, and "add a note" appears faintly beside the line you're on.
  - **The zoom controls** leave the status bar in this view, since there's no page to zoom. Desktop, tablets, the Scene Board and Plan are unchanged.

- **Phones: an element bar above the keyboard (mobile polish, round 2A).** While you write on a phone, a slim row on the keyboard's top edge offers Scene · Action · Character · Dialogue · ( ) · Transition, standing in for Tab and Alt+1…8.
  - Tapping one switches the line you're on, keeping the cursor or selection where it was. It's one undo step, like Alt+1…8.
  - It never takes the focus, so the keyboard stays up. The current element is underlined.
  - It keeps the line you're writing, and Character suggestions, clear of the keyboard.
  - It shows only on a phone-width touch screen with the cursor in the script, and never while Viewing, on the Board or in Plan. Desktop and tablets are unchanged.

- **Phones and touch screens (mobile polish, round 1).** Everything here applies only to a phone-width window or a touch screen; a desktop with a mouse is unchanged.
  - **File ▾ on a phone** opens as a sheet under the bar, 8px from each edge, and scrolls when it's taller than the screen. The bar's other menus scroll too.
  - **Touch screens** hide keyboard-shortcut hints (Alt+S, Ctrl+/, F1…) in menus, the Element list and the suggestion list. The ⋮ menu leaves out Keyboard Shortcuts, and the User Guide opens without its F1 / Ctrl+/ paragraph. Counts, file types and the printed guide are unchanged.
  - **Phones offer Page · Board.** Split doesn't fit two panes, so a phone shows Page instead. Jumping to a scene from the Board opens Page.
  - **Bigger tap areas on the top bar.** On a touch screen, each top-bar button takes a 44px-tall tap (5px wider on each side) through an invisible layer. The icons and buttons look the same.
  - **One panel at a time on phones.** Where panels fill the screen, opening Characters, the Story Bible, Snapshots or Margin Notes closes the Scenes list, and the other way round. Nothing in either is lost.
  - **iPhone and iPad: "Keep your pages safe" comes early, once.** In Safari (not from the Home Screen), the tip appears when the first scene is saved: a scene heading, 50+ words, never backed up, and not the sample. It's the same card and wording, with the Add to Home Screen line. Closing it in any way uses up the early showing; after that the usual 10 pages / 5,000 words rules apply. It never shows with a linked folder, and other platforms are unchanged.

Each row's **Add time…** lists DAY, NIGHT, MORNING, AFTERNOON, EVENING, CONTINUOUS and LATER; with two or more missing, **Add to all N…** beside the finding counts adds the same time to every one (snapshot first, one Ctrl+Z). - Tips for six easy-to-miss tools, each shown once, when it would help: **Import Scenes** (8+ scenes or 10+ pages, no scene cards yet), **Analyze Value Shifts** (scene cards, none with a Value Shift), **Populate Bio** (3+ characters whose introductions would fill an empty bio field), the **Format stepper** (5+ findings), the **Dialogue spotlight** (3+ speaking characters, 20+ speeches) and **Plan** (90+ pages). A small pulsing dot marks **Split** or **Characters** (or the **Bios** / **Dialogue** tab when Characters is open on the other); a card beside the tool gives two sentences, the tool's own button (**Spotlight MARIE** names your top speaker) and **Got it**; tools always on screen get the card straight away, flipped above the status bar with its notch pointing down. It never takes focus, runs nothing without a click, returns the cursor to the script after Import Scenes or Populate Bio, and waits for a calm moment (3 s after typing, a minute after a script opens; not in Focus, Plan, Viewing or under another corner card). It never overlaps anything: it hides while its tool is covered (a drawer, a dialog) or a menu, dropdown, hover card or toast would overlap it, and steps aside as soon as its button opens the tool. One new tip per session (Analyze may follow Import). Using a tool any way, even before its tip showed, ends its tip; states are saved per browser (`draftline_hints`). **⋮ → About DraftLine → Tips** is always shown: how many you've seen (**2 of 6 seen**), **Show tips again** to bring them back, and a confirmation once it's done. A tool counts as used at the moment you use it, so resetting sticks even with a character still spotlit, a Format finding selected or Plan open. Reduced motion turns off the pulse and slide.
- Story Bible → DNA → Glossary: a third section, **Screenplay Format**, with 19 terms. The page's elements come first, in the order they appear: Scene Heading (Slugline), Action, Character Cue, Dialogue, Parenthetical (Wryly), V.O. / O.S. / O.C., (CONT'D), (MORE), Dual Dialogue, Transition. Then, A–Z: Beat, Insert, Intercut, Montage / Series of Shots, One Page One Minute, Page Eighths, Pre-lap, Spec Script, Super. Like every glossary term they start as DraftLine's **starter** wording and can be replaced with your own. In the Format Doctor, a finding's chip (Scene heading format, Dangling parenthetical, Character cue without dialogue…) now opens the term that explains it, marked with a small book icon. The **starter** and **yours** badges explain themselves on hover, and the User Guide now walks through replacing a definition with your own.
- File → Final Draft opens **Export Final Draft**, with **Include margin notes (as Final Draft Script Notes)**. Checked, every margin note goes into the .fdx as a Final Draft `<ScriptNote>` on its element (multi-line notes kept line by line, notes in dual dialogue on their speech, a note on an empty line keeping that line), with the Script Note definition Final Draft keys them to. It's off by default, since margin notes are private, and the dialog says how many notes the script has (disabled with none). Saved per script as `fdxIncludeNotes`, in the library, backups and snapshot files; exporting another script from Projects follows that script's setting. Unchecked, the .fdx is byte for byte what it was before. Imported Script Notes still become margin notes, so notes now round-trip.
- User Guide: a **Final Draft (.fdx)** section under Export & Deliverables, with **What doesn't carry over to Final Draft**: 12A / locked scene numbers (renumbered 1, 2, 3…), Shot / act-break / Lyrics / Cast List elements (become Action), and Final Draft's own settings (SmartType, page layout, element settings, revision colours, All Caps display).
- Plan: a scene filter in the top bar's empty middle on Breakdowns and Stripboard: **Find scenes…** (heading, location, speaking character, or an exact scene number; capitals and accents ignored), **INT | EXT** and **DAY | NIGHT** (INT./EXT. counts as both). While set it shows **5 of 53 scenes ✕**, and the summary line counts scenes and pages shown. - Characters → Dialogue: in a cast of more than 15 speakers, the character pills fold after the 12 with the most lines, behind a dashed **+N more** pill (**Show fewer** folds them again; the choice is remembered), so the stats and speeches stay near the top. A picked character in the fold stays shown, lit, after the top 12.
- Characters → Dialogue: the **monologues** count is now a toggle. On, the speech list keeps only that character's monologues (over 5 printed lines or 60 words), each tagged **Monologue · N lines**, with Go ↗ to jump to it; click again, ✕, or pick another character to see every speech. Nothing is flagged in the script or the status bar.
- Format Doctor: **Unclosed parenthetical** ("beat", "(beat" → "(beat)", formatting kept); **Consecutive character cue** (the same speaker twice with nothing between → **Merge speeches**; cues that already say (CONT'D), differ in extension, or are dual dialogue are left alone); **Missing time of day** for a heading that has INT./EXT. (**Add - DAY** on its own row; Fix All skips it). "Parenthetical without dialogue after it" is now **Dangling parenthetical**, and its Make Action fix drops the parentheses.
- Format Doctor: **Leading spaces** — Action that starts with spaces or tabs ("   Dave jumped up.") is flagged, and **Remove leading spaces** fixes it with bold / italic kept in place. Only the first line counts, so indented lyrics or letters further down a paragraph aren't flagged. A scene heading with spaces before it is now caught as **Scene heading format** (its fix already removed them). Nothing is trimmed while you type.
- A backup tip: when a script saved only in this browser reaches 10 pages (or 5,000 words), a small card in the bottom-right corner suggests linking a folder, with **Link Folder** (opens Projects on the Linked Folder card), **Dismiss**, **Don't show again** and ✕. It never takes focus and waits while another corner toast or Focus mode is showing. In browsers that can't link a folder (Safari, Firefox, phones and tablets) it offers **Backup Project** (a .draftline download, reopened with File → Open) instead, and comes back once the script has been saved 7+ days after its last backup (from the tip or the File menu). Safari adds a line about Add to Dock (Mac) or Add to Home Screen (iPad, iPhone), which stops Safari clearing the site after a week away; it's left out when DraftLine is already opened that way.
